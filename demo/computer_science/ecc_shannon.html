香农极限（码率 1/2）
怎么读这张图

横轴 Eb/N0 是每信息比特的能量信噪比——这是唯一公平的比法：加了校验位就要多发符号，每个符号分到的能量就得摊薄。纵轴是误码率，越低越好。曲线越靠左越强。

三条竖线是同一个码率 1/2 下的理论天花板，右边是能做到的、左边是数学上不可能的：

  • 0 dB：不限制输入分布的香农极限。
  • 0.19 dB：输入只许 ±1（BPSK）时的极限，这才是这些码真正的对手。
  • 1.77 dB：先把每个符号硬判成 0/1 再纠错的极限。光是扔掉软信息就白送 1.6 dB。

点全都是实时蒙特卡洛跑出来的，不是查表画的。低误码率的点要攒很久，空心下箭头表示"这么多比特里一个错都没有，真值在箭头下面"。

结论剧透
  • 重复码是反面教材：重复 3 遍看着很稳，但为此码率掉到 1/3，换算成 Eb/N0 反而比不编码还差。（软判决合并的重复码则恰好与未编码完全重合——一点增益都没有。）
  • 汉明码 (7,4) 能纠 1 个错，高信噪比下小赚，低信噪比下赔本（一块里错两个反而被纠成更多错）。
  • 卷积码 K=7 + 软判决维特比是卫星/GSM 时代的主力，1e-5 处比不编码好约 5 dB，离极限还有 4 dB 多。
  • LDPC + 和积（BP）：瀑布区直接怼到极限附近几个分贝内，而且 n 越长越贴——这就是"逼近香农极限"的实感。
  • 同一个 LDPC 码换成硬判决比特翻转，立刻掉到 1.77 dB 那条线右边去。一半的功劳属于"软信息"，另一半属于码本身。

这一屏在干什么

把一张 64×64 的黑白图（4096 bit）切成 块，每块用 LDPC 码 编码后过同一个 AWGN 信道，再用和积算法迭代译码。

左二是没编码直接发的接收软值——灰度就是信道给出的"我觉得它是 0 还是 1，有多确信"。左三把它硬判成黑白：一堆椒盐噪声，这就是不纠错的下场。

最右是 LDPC 一次次迭代的结果。看它怎么从满屏雪花，几次迭代内"啪"地一下全对。下面的曲线是"还没被满足的校验方程数"，它归零的那一刻就是译码成功。

可玩的

  • 把 Eb/N0 拖到 1.5 dB 以下，LDPC 也开始扛不住了——瀑布区的边缘就在那儿。
  • 拖到 4 dB，未编码仍然一身麻子，LDPC 两三次迭代就干净了。
  • "重采噪声"多按几次：在瀑布区边缘，同样的信噪比有时成功有时失败，这就是误块率的来源。

给七个码同一种破坏，各跑几十次，看它们分别活成什么样。 绿=完好无损，黄=知道自己错了（可以要求重发），红=输出了错数据还一声不吭（最危险的一种）。

七个码一眼对照
值得试的三组对比
  • 突发 ↔ 散错来回切：RS 码和卷积码的成绩会几乎对调。RS 按"符号"纠错，一片连错只脏掉少数几个符号；卷积码靠上下文推理，一片连错直接把推理链冲断。
  • 勾上交织器（发之前打乱顺序、收到后还原，把连错撒成散错）：卷积码起死回生，RS 码反被害死。CD 和深空探测用的"RS + 交织 + 卷积"级联就是这么来的。
  • 把错误量拉大：每个码都有一道断崖。注意红色（悄悄出错）什么时候开始长出来——那才是真正危险的区域。

和积算法（BP）在做什么

这是一个玩具 LDPC 码的 Tanner 图：下排圆圈是 变量节点（每个 = 一个比特），上排方块是 校验节点（每个 = 一条异或方程"我连的这些比特加起来必须是偶数"）。

译码就是这两排人反复交换置信度（LLR）：

  • 变量 → 校验：我把信道给我的意见、加上除你之外其他校验对我的意见，汇总后告诉你。
  • 校验 → 变量：我看我连的其他比特都说自己是啥，推出你应该是啥。符号相乘、幅度取最小——一群人里最不确定的那个决定了这条推断有多可信。

关键在那个"除你之外"：不把你自己的话再还给你，信息才不会自我循环放大。图上有环（girth），所以这只是近似——但在长码上近似得惊人地好。

颜色

绿=倾向 0（发的是全零码字，所以绿色是对的），红=倾向 1（错），越深越确信。校验方块红色=当前不满足。

点一个校验方块看它这一轮的具体算式；点一个变量圆圈可以手动把它的信道值翻成错的，看 BP 怎么把它救回来（或者救不回来）。
